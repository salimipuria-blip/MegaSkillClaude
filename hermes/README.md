# هرمس: دستیار ۲۴/۷ در تلگرام

هزینه: ۰. دو نسخه دارد:

| | **هرمس لایت** (پیشنهادی) | هرمس کامل |
|---|---|---|
| کجا اجرا می‌شود | Cloudflare Workers | سرور Oracle Always Free |
| کارت بانکی خارجی | لازم نیست | لازم است (اوراکل ایران را نمی‌پذیرد) |
| سرور یا دستگاه روشن | لازم نیست | سرور اوراکل |
| چه می‌کند | چت با جمینی، حافظهٔ دائمی + ۴۰ پیام اخیر، فقط برای تو | ایجنت کامل هرمس با ابزار و اجرای دستور روی سرور |
| فایل‌ها | `entry.mjs`، `worker.mjs`، `wrangler.toml` | `setup.sh` |

## هرمس لایت روی Cloudflare

KV قبلی (`hermes-memory`) برای حساب‌ها و دادهٔ قدیمی در `wrangler.toml` وصل است. حافظهٔ
گفتگوهای جدید با binding `CONVERSATIONS` در **SQLite Durable Object** نگه‌داری می‌شود؛ migration
`conversation-sqlite-v1` همراه انتشار اعمال می‌شود. پیام‌ها/یادداشت‌های فعلی KV در اولین دسترسی
هر گفتگو یک‌بار منتقل می‌شوند، بدون حذف مبدأ یا بایگانی‌های قبلی. تنظیم
`REQUIRE_CONVERSATIONS=true` نبودِ binding را خطا می‌کند، نه بازگشت بی‌صدا به حافظهٔ ناامن.
این کد محلی تست شده؛ وضعیت binding و انتشار واقعی را پس از deploy بررسی کنید.

**۱. سه چیز آماده کن** (جایی ننویس و برای کسی نفرست)
- **کلید جمینی:** aistudio.google.com ← Get API key. با VPN.
- **توکن بات:** از `@BotFather` ← `/newbot`. اگر بات داری، `/token`.
- **شناسهٔ عددی تلگرام:** به `@userinfobot` پیام `/start` بده.

> **کلید جمینی اختیاری است.** اگر نباشد یا گوگل آن را رد کند (مثلاً 403)، بات خودکار از هوش مصنوعی رایگان خود Cloudflare (Workers AI) استفاده می‌کند. نه کلید می‌خواهد و نه VPN.

**۲. ساخت Worker از همین مخزن**
dash.cloudflare.com ← Workers & Pages ← Create ← **Import a repository** ← GitHub ← `MegaSkillClaude`
- Project name: `hermes` (دقیقاً همین)
- Root directory: `hermes`
- Deploy command: `npx wrangler deploy` (پیش‌فرض)
- ← Deploy

از این به بعد هر تغییری که در پوشهٔ `hermes/` روی `main` برود، خودکار منتشر می‌شود.

**۳. رمزها**
Worker `hermes` ← Settings ← Variables and Secrets ← Add. هر سه را با نوع **Secret** اضافه کن:

| Name | Value |
|---|---|
| `TELEGRAM_BOT_TOKEN` | توکن BotFather |
| `GEMINI_API_KEY` | کلید جمینی |
| `GITHUB_MODELS_TOKEN` | (اختیاری، رایگان) توکن گیت‌هاب با دسترسی Models — مغز پشتیبان GPT-4.1 |
| `GROQ_API_KEY` | (اختیاری، رایگان) کلید console.groq.com — مغز پشتیبان سریع |
| `CEREBRAS_API_KEY` / `OPENROUTER_API_KEY` / `MISTRAL_API_KEY` | (اختیاری، رایگان) مغزهای پشتیبان بیشتر |
| `HEALTH_KEY` | (اختیاری) یک رشتهٔ تصادفی طولانی برای `GET /health/deep` و workflow «Hermes live health»؛ همان مقدار در secretهای GitHub با نام `HEALTH_KEY` |
| `HF_TOKEN` | (اختیاری، رایگان) توکن huggingface.co/settings/tokens — هم مغز (DeepSeek/Llama/Qwen) و هم ساخت عکس FLUX |
| `STABILITY_API_KEY` | (اختیاری، رایگان) کلید platform.stability.ai — «کیفیت نهایی»: بزرگ‌کردن خروجی ویرایش با upscaler واقعی |
| `ALLOWED_USER_ID` | شناسهٔ عددی تو |

> اگر رمزها را اشتباهی در Settings ← Build ← Variables and secrets گذاشتی، مشکلی نیست: `sync-secrets.mjs` موقع هر ساخت آن‌ها را به رمزهای خود بات کپی می‌کند.

**۴. فعال‌سازی خصوصی:** صفحهٔ اصلی فقط وضعیت روشن‌بودن Worker را می‌گوید و دیگر webhook را
تغییر نمی‌دهد. `/setup` فقط POST با کلید جداگانهٔ مالک را می‌پذیرد؛ بازکردن لینک در مرورگر کافی نیست.
اگر webhook فعلی روی همین Worker و با همین توکن بات کار می‌کند، نیاز به ثبت دوباره نیست.
برای اولین اتصال/تعمیر، در محیط محلی قابل اعتماد `TELEGRAM_BOT_TOKEN` و `ALLOWED_USER_ID` را
همسان با تنظیمات Worker قرار بده (نه داخل Git و نه در چت)، سپس از ریشهٔ مخزن:

```bash
HERMES_URL=https://hermes.<your-subdomain>.workers.dev npm run setup:webhook --prefix hermes
```

آدرس را با origin واقعی جایگزین کن؛ دستور کلید راه‌اندازی را خودش می‌سازد و فقط در هدر درخواست
می‌فرستد، نه در URL یا خروجی. این کار عمداً در hook نصب/تست اجرا نمی‌شود.

**۵. تست:** در تلگرام به بات بنویس «سلام، خودت را معرفی کن».

### اپ چت (مثل ChatGPT)
در **چت خصوصی** تلگرام به بات بنویس `/app`؛ یک لینک خصوصی می‌دهد. بات در گروه/کانال جواب نمی‌دهد. لینک‌های مالک مربوط به قبل از سخت‌سازی 2026-10-12 پس از انتشار نامعتبرند؛ لینک تازه بگیر. در سافاری بازش کن و **Share ← Add to Home Screen** را بزن تا مثل اپ روی صفحهٔ اصلی بیاید. حافظهٔ اپ با چت تلگرام یکی است. لینک را برای کسی نفرست؛ هر کس آن را داشته باشد می‌تواند با هرمس حرف بزند.

ظاهر اپ: مثل APEX-UI. هستهٔ ذره‌ای داخل حلقهٔ طلایی وسط یک شبکهٔ مدار است. هر گره یکی از توانایی‌های هرمس است؛ آبی یعنی فعال، طلایی یعنی مهارت، خاکستری یعنی در راه. روی هر گره بزنی کارتش باز می‌شود و نمونه‌پیام‌هایش را می‌شود همان‌جا فرستاد. موقع فکر کردن، گره‌هایی که به کار می‌آیند روشن می‌شوند. بالا-چپ ساعت و هوا، بالا-راست تاریخچهٔ گفتگو. طراحی از APEX-UI (مجوز MIT، Ruben Mouradian) الهام گرفته و همه‌اش در `app.mjs` از نو نوشته شده.

### حافظه و مهارت‌ها
- **همهٔ پیام‌ها برای همیشه ذخیره می‌مانند.** هرمس برای جواب، ۴۰ پیام آخر را می‌بیند. «گفتگوی جدید» یا `/reset` گفتگو را بایگانی می‌کند، پاک نمی‌کند.
- **یادداشت بلندمدت:** بنویس «یادت باشه ...» یا «remember that ...». همیشه در نظرش می‌ماند. `/notes` فهرست، `/forget` پاک کردن. در اپ: تاریخچه ← LONG-TERM MEMORY.
- **یادآور (جدید):** بنویس «یادم بنداز ساعت ۹: تماس با بانک» یا «یادم بنداز فردا ۱۰: قرار دکتر» یا «یادم بنداز ۲۰۲۶-۱۰-۲۰ ۰۹:۰۰: مراجعه به بیمه» یا انگلیسی «remind me in 30 minutes: call Bob». سر وقت از تلگرام پیام می‌گیری و هر روز ساعت ۸ صبح **برنامهٔ روزت** را می‌فرستم. `/reminders` فهرست (با شماره)، `/rem_del ۲` حذف. در اپ هم کار می‌کند: تاریخچه ← REMINDERS، هر ردیورد را با ✕ پاک کن.
  - برای فعال شدن پیام خودکار، در `hermes/wrangler.toml` بخش `[triggers]` را از حالت کامنت خارج کن و دوباره deploy کن (بدون آن، یادآورها ذخیره و فهرست می‌شوند ولی پیام نمی‌روند).
- **ویس:** در تلگرام ویس بفرست؛ در اپ دکمهٔ میکروفون را بزن، حرف بزن، دوباره بزن. اول متن ویس را نشان می‌دهد، بعد جواب می‌دهد (Gemini، پشتیبان Whisper روی Workers AI).
- **عکس:** در تلگرام عکس (با یا بی کپشن) بفرست؛ در اپ دکمهٔ دوربین. هرمس عکس را می‌بیند و جواب می‌دهد (Gemini، پشتیبان LLaVA).
- **ویرایش حرفه‌ای عکس (۴ مرحله):** عکس خودت را بفرست و بنویس چه تغییری می‌خواهی؛ نتیجه به‌صورت **قبل/بعد** برمی‌گردد. مراحل داخلی:
  ۱) **بریف:** مدل بینایی عکس را می‌خواند و «چه چیزی باید حفظ شود، چه ایرادی باید درست شود، نور/رنگ/کادر» را می‌نویسد؛
  ۲) **ویرایش:** دستور از روی کتابخانهٔ مهارت‌ها ساخته می‌شود (ریتوش پرتره، عکس محصول استودیویی، پس‌زمینه، نورپردازی، گرید سینمایی، بازسازی عکس قدیمی، افزایش کیفیت، حذف شیء، تعویض شیء، بزرگ‌کردن کادر، تغییر سبک) — با Gemini image-edit و پشتیبان img2img روی Workers AI؛
  ۳) **بازبینی:** نتیجه با عکس اصلی مقایسه می‌شود (چهره/هویت، متن‌های موجود، کادر، شیء اضافه‌شده) و اگر رد شود، یک بار دیگر با «نکتهٔ بازبینی» ساخته می‌شود؛
  ۴) **تحویل:** کپشن فارسی کوتاه با «چه اصلاح شد» و «اگر بخواهی چه چیز دیگری می‌شود».
  - مثال‌ها: «این عکس رو ریتوش کن»، «پس‌زمینه رو عوض کن»، «نور غروب بده»، «رنگش رو سینمایی کن»، «این عکس قدیمی رو بازسازی کن»، «کیفیتش رو بالا ببر»، «این یارو رو از عکس حذف کن»، «مثل عکس محصول استودیویی دربیار».
  - **نوشتن متن روی عکس (لایهٔ متن):** بنویس «روی عکس بنویس: کمپ وایکینگ» یا «متن بذار پایین عکس «تور آفرود دو روزه» با فونت طلایی و نوار». متن با **فونت واقعی وزیرمتن** می‌نشیند (مدل تصویر هرگز متن نمی‌کشد، چون فارسی را خراب می‌کند) و در اپ دکمه‌های **بالا/وسط/پایین** و **ذخیرهٔ PNG** دارد. اگر `BROWSER` (Cloudflare Browser Rendering) روی حساب وصل باشد، تلگرام هم عکس متن‌دار می‌فرستد؛ وگرنه همان عکس + دستور یک‌خطی اپ می‌آید.
  - **چرخاندن همان متن با پیام (بدون فرستادن دوبارهٔ عکس و بدون هیچ مدل تصویر):** «بالاتر ببر»، «کمی پایین‌تر»، «وسطش بذار»، «متن رو ببر بالای عکس»، «سفیدش کن»، «رنگش طلایی کن»، «درشت‌ترش کن»، «کوچیکش کن»، «نوار بذار پشتش»، «بدون نوار»، «متن رو عوض کن به «…»» (با حفظ جا و رنگ) و «متن رو بردار». چند تغییر در یک پیام هم می‌شود. لایه یک ساعت در حافظه می‌ماند؛ در اپ همان کار با دکمه‌های **بالا/وسط/پایین** و **ذخیرهٔ PNG** هم انجام می‌شود.
  - **قواعد سخت:** هویت/چهره/سن دست‌نخورده می‌ماند (مگر خودت تغییر سبک هنری بخواهی)؛ متن فقط با فونت واقعی نوشته می‌شود (لوگو/گرافیک رسم نمی‌شود)؛ اگر هیچ مدلی جواب ندهد، صادقانه خطا می‌دهد؛ هرگز عکس جعلی/ویرایش‌نشده تحویل نمی‌شود.
  - **چند نسخه:** بنویس «چند نسخه» تا سه نسخهٔ محافظه‌کارانه/متعادل/جسورانه بسازم، با کیفیت هر نسخه
    (امتیاز بازبینی از ۱۰۰) و پیشنهاد من. در اپ همه با هم نشان داده می‌شوند.
  - **بدون فرستادن دوبارهٔ عکس:** تا یک ساعت بعد از هر ویرایش می‌توانی بگویی «ملایم‌تر» یا «قوی‌تر»؛
    همان نقشهٔ ویرایش با شدت کمتر/بیشتر دوباره اجرا می‌شود.
  - **انتخاب نسخه:** در اپ زیر هر نسخه دکمهٔ «همین را انتخاب کن» هست و در تلگرام کافی است بنویسی
    «نسخهٔ ۲»؛ همان نسخه با همان شدت خودش دقیق‌تر بازسازی می‌شود.
  - **کیفیت نهایی (اختیاری):** اگر عکس اصلی بزرگ‌تر از خروجی مدل باشد (مدل‌های رایگان ~۱۰۲۴px می‌دهند)
    و `STABILITY_API_KEY` تنظیم شده باشد، خروجی با upscaler واقعی Stability بزرگ می‌شود و در کپشن
    می‌آید («کیفیت نهایی: ۲۰۴۸×۲۰۴۸»). بدون کلید، این پله صادقانه رد می‌شود و اصل عکس دست‌نخورده می‌ماند.
  - **کیفیت چگونه تضمین می‌شود:** نسخه‌ها با روبریک وزنی امتیاز می‌گیرند (انجام درخواست، حفظ هویت،
    نبود آرتیفکت، نور و رنگ، کادر). نسخهٔ زیر سقف کیفیت یا با هویت آسیب‌دیده تحویل نمی‌شود مگر
    بهترین گزینه باشد و آن‌وقت صادقانه در کپشن گفته می‌شود. ابعاد واقعی خروجی هم دیکود و چک می‌شود.
  - گرهٔ **Photo Lab** در اپ همین توانایی است و وقتی پیام ویرایش بفرستی روشن می‌شود.
- **جست‌وجوی گوگل:** برای خبر، قیمت و چیزهای روز خودش در گوگل می‌گردد و منبع می‌آورد.
- **ساخت عکس:** بنویس «عکس بساز: ...» (یا `/img ...`). بهترین مدل‌های رایگان کلادفلر به ترتیب کیفیت: FLUX.2 [dev] ← Leonardo Lucid Origin ← Leonardo Phoenix ← FLUX.2 [klein] ← FLUX.1 schnell؛ همه بدون واترمارک و از سهمیهٔ رایگان روزانهٔ Workers AI. اندازه از متن: «استوری» ۹:۱۶، «پست» ۴:۵، «بنر» ۱۶:۹. برای خروجی‌های اجتماعی وایکینگ، پرامپت اختصاصی از روی راهنمای `brand/viking/ART_DIRECTION.md` ساخته می‌شود؛ مدل فقط عکس پایهٔ فوتورئالیستی و سینماتیک را می‌سازد و متن فارسی/لوگو باید با فونت واقعی و فایل برند چیده شوند، نه با مدل تصویر. پرامپت «جزئیات بصری 8K-like» را می‌خواهد، اما مسیر اصلی فعلاً ۱۰۲۴×۱۲۸۰ برای پست و ۷۲۰×۱۲۸۰ برای استوری درخواست می‌کند، نه ۸K واقعی؛ سرویس ممکن است اندازهٔ دیگری برگرداند، پس وضوح را فقط پس از بررسی ابعاد واقعی ادعا کن. Gemini image فقط اگر حساب گوگل پولی باشد. بعد Hugging Face FLUX (اگر `HF_TOKEN` باشد). اگر سهمیهٔ کلادفلر تمام شده باشد، عکس از سرویس رایگان و بدون کلید Pollinations (FLUX) ساخته می‌شود (با `FREE_IMAGES=off` خاموش می‌شود).
- **گوگل (فقط مالک):** جیمیل (خواندن و پیش‌نویس؛ هرگز خودش نمی‌فرستد)، تقویم (دیدن و ساختن رویداد)، درایو (جست‌وجو) و شیت (خواندن و اضافه کردن ردیف). مثلاً «ایمیل‌های خوانده‌نشدهٔ امروز رو خلاصه کن»، «فردا ساعت ۱۰ جلسه با حسام بذار»، «این رزرو رو به شیت رزروها اضافه کن».

- **صفحهٔ سفر و رزرو (عمومی):** `https://<worker>.workers.dev/trip` — لینک بیو. در تلگرام `/trip` لینک را می‌دهد. مسافر فرم را پر می‌کند ← مشخصات رزرو (نام، شماره، تعداد، خودرو، توضیح) به‌صورت پیام خصوصی فقط برای مالک (صاحب شمارهٔ رزرو) در تلگرام فرستاده می‌شود. اطلاعات پرداختی از اینجا ارسال نمی‌شود؛ تیم خودش با مسافر تماس می‌گیرد. بعد از پرداخت کنسلی ندارد.
  - **مسئول رزرو (فقط یک نفر):** صاحب شمارهٔ رزرو (`BOOKING_PHONE`؛ پیش‌فرض داخل کد فقط به‌صورت هش ذخیره شده) یک بار به بات پیام می‌دهد و دکمهٔ «📱 ارسال شمارهٔ من» را می‌زند. اگر شماره خودش باشد و بخواند، از آن به بعد گزارش رزروها فقط برای همان حساب می‌رود و به مالک خبر داده می‌شود. تا قبل از ثبت، گزارش فقط برای مالک می‌رود (شماره مال خود مالک است).
  - `BOOKING_ADMIN_IDS` (اختیاری): آیدی عددی تلگرام بقیهٔ اعضای تیم، با کاما. هر نفر باید یک بار به بات پیام بدهد (بات آیدی‌اش را جواب می‌دهد) — تلگرام با شمارهٔ تلفن پیام نمی‌فرستد.
  - اطلاعات سفر (عنوان، تاریخ، قیمت) در `hermes/booking.mjs` (ثابت `TRIP` و متن صفحه) است.
  - محدودیت فرم رزرو: حداکثر ۵ درخواست در هر پنجرهٔ یک‌ساعته برای هر IP؛ پاسخ 429 زمان انتظار را در `Retry-After` می‌فرستد. شمارنده در KV و به‌صورت best-effort است؛ KV افزایش اتمیک تضمین نمی‌کند، پس این کنترل جلوی حملهٔ توزیع‌شده یا تقلب را به‌تنهایی نمی‌گیرد. در صورت نبودن/خطای KV رزرو fail-closed و موقتاً 503 می‌شود.

### اتصال گوگل (یک بار)
1. console.cloud.google.com → پروژهٔ جدید «Hermes».
2. APIs & Services → Library: این‌ها را Enable کن: Gmail API، Google Calendar API، Google Drive API، Google Sheets API.
3. Google Auth Platform → Branding (نام Hermes و ایمیل) → Audience: External و **Publish app** (وگرنه اتصال هر ۷ روز قطع می‌شود؛ هشدار «unverified» برای استفادهٔ شخصی عادی است).
4. Clients → Create client → Web application → Authorized redirect URI: `https://<worker>.workers.dev/connect/google/callback`
5. Client ID و Client secret را در کلادفلر (Workers → hermes → Settings → Variables and Secrets، نوع Secret) با نام‌های `GOOGLE_CLIENT_ID` و `GOOGLE_CLIENT_SECRET` بگذار. در چت نفرست.
6. در تلگرام `/google` را بزن، لینک یک‌بار مصرف را باز کن و اجازه بده. قطع: `/google_off`.
- **مهارت‌ها:** روش کار و دستورالعمل‌های محتوا، تور، برنامه‌ریزی، ویرایش، ترجمه، پژوهش و کد در `skills.mjs` است.
- **کتابخانهٔ کامل مهارت‌ها (Mega Skills):** همهٔ ۶٬۰۱۷ مهارت مخزن (`plugins/mega-skills-router`) موقع دیپلوی با `build-skills.mjs` به فایل‌های داخلی Worker تبدیل می‌شوند. ۲۸۱ مهارت ناقص از مسیریابی خودکار کنار گذاشته شده‌اند (۵٬۷۳۶ مهارت فعال). برای هر پیام، `skill-router.mjs` تا ۳ مهارت مرتبط را پیدا می‌کند و دستورالعملشان را به هرمس می‌دهد. پیام‌های معمولی مثل «سلام» بدون مهارت جواب داده می‌شوند.
- **ارتقا:** کارهای بعدی در [`ROADMAP.md`](ROADMAP.md). یک روتین روزانه (۹:۵۵ صبح تهران) اولین کار باز را می‌سازد و PR می‌دهد.

### حساب‌های تیم
اپ برای هم‌تیمی‌ها با نام کاربری و رمز باز می‌شود. هر نفر حافظهٔ گفتگوی جداگانهٔ خودش را دارد. مالک همچنان با لینک `/app` تلگرام وارد می‌شود و حافظه‌اش با تلگرام یکی است.

| نقش | دسترسی |
|---|---|
| مالک | همه‌چیز، با لینک تلگرام |
| ADMIN | همهٔ ابزارهای هوش مصنوعی، دیدن فهرست تیم، تغییر رمز خودش؛ تغییر ساختار ندارد |
| VIKING (عضو) | همهٔ ابزارهای هوش مصنوعی، حافظهٔ شخصی، تغییر رمز خودش |

**قفل‌ها:** هر حساب می‌تواند `locks` داشته باشد. هرمس درخواست دربارهٔ موضوع قفل‌شده را قبل از فرستادن به هوش مصنوعی رد می‌کند و گره‌اش در اپ با 🔒 قرمز دیده می‌شود. فعلاً:
- پوریا: «وایکینگ» قفل، FJCod باز
- بقیه: FJCod قفل، وایکینگ باز
- مالک: همه‌چیز باز

حساب‌ها در `users.mjs` هستند. آنجا فقط هش رمزها ذخیره می‌شود (PBKDF2، ۱۰۰ هزار دور)، نه خود رمز. افزودن نفر جدید:
```bash
node hermes/add-user.mjs <username> "<نام>" member
```
رمز را یک بار چاپ می‌کند (خصوصی بده). خطی که چاپ می‌کند را در `users.mjs` بگذار و مرج کن. بعد از ۸ رمز اشتباه، ورود آن نام کاربری ۱۵ دقیقه بسته می‌شود.

### دستورها در تلگرام
- `/start`: خوش‌آمد
- `/reset`: گفتگوی تازه و بایگانی قبلی، بدون حذف
- `/app`: لینک خصوصی اپ چت

### اگر گیر کردی

| پیام | راه حل |
|---|---|
| `✗ Missing secrets: ...` | همان رمزها را در قدم ۳ اضافه کن، بعد دستور خصوصی `setup:webhook` را دوباره اجرا کن |
| `✗ Telegram rejected ...` | توکن را دوباره از BotFather کپی کن |
| بات می‌گوید «این بات خصوصی است» | عددی که بات نشان داده را در `ALLOWED_USER_ID` بگذار |
| «جمینی کلید را نپذیرفت» | کلید تازه در AI Studio بساز و Secret را عوض کن |
| «سهمیهٔ رایگان جمینی پر است» | محدودیت رایگان گوگل است؛ چند دقیقه صبر کن |
| بات هیچ جوابی نمی‌دهد | دستور خصوصی `setup:webhook` را دوباره اجرا کن. اگر درست نشد: Worker ← Logs، اسکرین‌شات بفرست |

### محدودیت‌های رایگان
- Cloudflare: روزی ۱۰۰٬۰۰۰ درخواست.
- KV حساب‌ها/دادهٔ قدیمی و SQLite Durable Objects گفتگو سهمیه‌های جدا دارند؛ سقف و شرایط فعلی سطح رایگان را در حساب Cloudflare بررسی کن. هیچ ارتقای پولی خودکار فعال نکن.
- جمینی: سهمیهٔ رایگان AI Studio.

تست واحد بدون وابستگی: `npm test --prefix hermes` (۱۷۹ تست: بات + CLI راه‌اندازی + استودیوی ویرایش عکس + لایهٔ متن و چرخاندنش با پیام).
تست واقعی ذخیره‌سازی/هم‌زمانی در workerd محلی: `npm ci --prefix hermes --ignore-scripts` و
`npm run test:integration --prefix hermes`. `--ignore-scripts` مانع اجرای sync-secrets در تست می‌شود.
تمام upstreamهای تست شبیه‌سازی شده‌اند؛ تست‌ها به بات/مدل/دادهٔ واقعی دست نمی‌زنند.
مراحل انتشار و محدودیت‌ها: [گزارش سخت‌سازی](../docs/REPO_HARDENING.md).

**سلامت و مشاهده‌پذیری (Lite):** `GET /health/live` (زنده‌بودن)، `/health/ready` (آمادگی؛ ۵۰۳ تا پیکربندی کامل شود)، `/health/full` و `/metrics` (Prometheus یا `?format=json`) — بدون افشای هیچ رازی. تست اسکریپت‌های نصب: `bash hermes/tests/setup_validation.sh`. نصب non-interactive، عیب‌یابی و runbook عملیات: [docs/hermes/INSTALL.md](../docs/hermes/INSTALL.md)، [docs/hermes/OPERATIONS.md](../docs/hermes/OPERATIONS.md)، [docs/hermes/observability.md](../docs/hermes/observability.md). برنامهٔ ۱۰۰ تسک و ابزار اجرای امن آن: [tasks/README.md](../tasks/README.md).

## هرمس کامل روی Oracle (فقط با کارت خارجی واقعی)

اوراکل برای ساخت حساب کلاد کارت ویزا یا مستر به نام خودت و آدرس خارج از ایران می‌خواهد. با اطلاعات جعلی ثبت‌نام نکن، چون حساب و سرور بسته می‌شوند.

**A. ساخت سرور** (کنسول اوراکل)
- مسیر: Compute ← Instances ← Create instance
- Image: Ubuntu 24.04 (aarch64)
- Shape: `VM.Standard.A1.Flex` با ۴ OCPU و ۲۴ گیگابایت رم. برچسب **Always Free** باید دیده شود.
- SSH keys: Generate a key pair for me، بعد **Save private key**
- اگر Out of capacity گرفتی: ۲ OCPU و ۱۲ گیگابایت.

**B. اتصال** با Termius: Host = آی‌پی عمومی، User = `ubuntu`، Key = کلید خصوصی

**C. نصب** (یک خط)
```bash
curl -fsSL https://raw.githubusercontent.com/salimipuria-blip/MegaSkillClaude/main/hermes/setup.sh -o setup.sh && bash setup.sh
```
اسکریپت کلید جمینی، توکن بات و شناسهٔ عددی را می‌پرسد. کلید و توکن موقع تایپ دیده نمی‌شوند و فقط روی همان سرور ذخیره می‌شوند. هرمس به صورت سرویس systemd اجرا می‌شود و بعد از ری‌استارت هم بالا می‌آید.

**نگهداری:** `hermes gateway status`، `hermes gateway restart`، `hermes doctor`. اگر بات ساکت ماند: `journalctl --user -u hermes-gateway -n 50 --no-pager`.


**ترتیب مغزها:** جمینی (همهٔ مدل‌ها) ← GitHub Models ← Groq ← Cerebras ← OpenRouter ← Workers AI. هر کدام که کلیدش نباشد رد می‌شود؛ پر شدن سهمیهٔ یکی، نوبت را به بعدی می‌دهد. نام مدل‌ها را می‌شود با `GITHUB_MODELS`، `GROQ_MODELS` و … (جداشده با کاما) عوض کرد.
