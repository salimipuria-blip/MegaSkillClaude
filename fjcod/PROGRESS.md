# CHAM Store OS (FJCOD) — دفتر جریان پروژه

> توضیح زندهٔ پروژه؛ هر دور کاری همین‌جا اضافه می‌شود. آخرین به‌روزرسانی: **۲۰۲۶-۱۰-۱۴**.

## ۱) پروژه در یک نگاه
- **پوشه:** `fjcod/` · **انتشار:** Vercel `cham-store-os` (هنوز از مخزن قدیمی `FJCod` — بند P0 نقشهٔ راه)
- **فناوری:** React 19 + TypeScript + Vite 7 · داده فعلاً فقط در مرورگر (بدون بک‌اند)
- **تست:** Vitest (۳۳ تست) + `scripts/e2e-smoke.mjs` (Playwright-Core)

## ۲) دستور دقیق این پروژه
```bash
node scripts/doctor.mjs fjcod        # typecheck + ۳۳ تست + بیلد (+ e2e اگر مرورگر باشد)
```
معادل دستی:
```bash
cd fjcod
npm ci
npm run typecheck        # tsc -b
npm test                 # vitest run → ۳۳ تست
npm run build            # tsc -b && vite build
npm run build && npm run e2e   # اسموک مرورگر (نیازمند Chromium)
```

## ۳) وضعیت تأییدشده (۲۰۲۶-۱۰-۱۴)
| بررسی | نتیجه |
|---|---|
| `npm run check` (typecheck + test + build) | ✅ **۳۳/۳۳** تست، باندل `index.js` ۳۷۴kB (gzip ۱۱۴kB) |
| `npm run e2e` با Chromium headless 153 | ✅ **۱۹/۱۹** مرحله؛ ورود نقش‌ها، صندوق/سبد، شیفت، بدون console error؛ دسکتاپ و viewport موبایل 390×844 |
| `npm run e2e` بدون مرورگر | ✅ خروج ۰ با پیام «skip»؛ `E2E_STRICT=1` خروج ۲ (قرارداد skip/fail-closed هم تأیید شد) |
| `npm audit --omit=dev` | ✅ صفر آسیب‌پذیری |

## ۴) دیباگ این دور (مشکل واقعی و اصلاح‌شده)
**`npm run e2e` روی هر ماشین تازه کرش می‌کرد.** `playwright-core` هیچ مرورگری همراه ندارد و
اسکریپت فقط دو مسیر را می‌شناخت (`CHROMIUM_PATH` و یک مسیر ثابت
`/opt/pw-browsers/chromium-1194/...` که به شمارهٔ نسخهٔ Playwright گره خورده). نتیجه: خروج غیرصفر با
بنر نامفهوم Playwright، و اگر خطا قبل از پایان رخ می‌داد **سرور preview روی پورت ۴۱۷۹ رها می‌شد**.

اصلاحات در `scripts/e2e-smoke.mjs`:
1. **جست‌وجوی هوشمند مرورگر:** `CHROMIUM_PATH` → `PLAYWRIGHT_BROWSERS_PATH` → کش Playwright
   (`~/.cache/ms-playwright/chromium*/…`) → `/opt/pw-browsers` (همهٔ نسخه‌ها، جدیدترین اول) →
   Chrome/Chromium سیستمی (`which`) → مسیرهای پیش‌فرض macOS/Windows.
2. **شکست با پیام قابل‌عمل:** اگر مرورگری نبود، سه راه‌حل دقیق چاپ می‌شود
   (`npx playwright install chromium` / `CHROMIUM_PATH=…` / `E2E_STRICT=1`) و خروج **۰ (skip)**؛
   با `E2E_STRICT=1` یا `--strict` خروج **۲**. دیگر هیچ بنر گنگی چاپ نمی‌شود.
3. **پاک‌سازی تضمینی:** `process.on('exit'|'SIGINT'|'SIGTERM')` سرور preview را می‌بندد و
   اگر ساخت سرور شکست بخورد، پیام دقیق («اول `npm run build`») با خروج ۱ داده می‌شود.
4. خط اول اسکریپت حالا رفتارش را مستند می‌کند (چرا skip، چطور فعال شود).

## ۶) لاگ جریان (فقط اضافه می‌شود)
- **۲۰۲۶-۱۰-۱۴** — رفع کرش `npm run e2e` (شناسایی چندمسیرهٔ مرورگر + skip با پیام دقیق +
  حالت `E2E_STRICT`)، تضمین بسته‌شدن پورت preview، مستندسازی رفتار اسکریپت. تست‌ها ۳۳/۳۳ سبز.
- **۲۰۲۶-۱۰-۱۴ (گیت کامل monorepo)** — نصب تمیز `npm ci` و `node scripts/doctor.mjs fjcod` موفق؛ typecheck، **۳۳ تست Vitest** و build سبز. در همان مرحله Chromium system پیدا نشد و E2E skip شد.
- **۲۰۲۶-۱۰-۱۴ (مرورگر موقت)** — Chromium headless از بستهٔ npm در `/tmp` استخراج و با `LD_LIBRARY_PATH` لازم اجرا شد؛ پس از build، `CHROMIUM_PATH=/tmp/chromium npm run e2e` واقعاً اجرا شد: **۱۹/۱۹ مرحله سبز**، بدون خطای console، شامل دسکتاپ، viewport موبایل 390×844، نقش‌ها، فروش و بستن شیفت. مرورگر/iOS Safari واقعی نیست؛ فایل‌های screenshot فقط در `e2e-shots/` نادیده‌گرفته‌شده‌اند.
- **۲۰۲۶-۱۰-۱۴ (بازاجرای نهایی)** — `CHROMIUM_PATH=/tmp/chromium LD_LIBRARY_PATH=/tmp/al2023/lib npm run e2e`: **۱۹/۱۹** دوباره سبز؛ تأیید کرد که نتیجهٔ full doctor با binary صریح مرورگر نیز قابل تکرار است. Safari/iPhone واقعی همچنان خارج از این smoke است.

- **۲۰۲۶-۱۰-۱۴ (دور سراسری — باگِ حسابداریِ مرجوعی + ۸ تست جدید)** — نوشتنِ تست برای «مسیر مدیر: مرجوعی + بازگشت به انبار» یک باگ واقعی در مغازهٔ داده پیدا کرد:
  - **`expectedCash()` مرجوعی را به شیفتِ غلط نسبت می‌داد.** فروش‌ها با `s.shiftId === shift.id` فیلتر می‌شدند ولی مرجوعی‌ها با «زمان + شخصِ ثبت‌کننده» (`r.at >= shift.openedAt && r.by === shift.userId`). در عمل صندوقدار می‌فروشد و **مدیر** مرجوع می‌کند؛ پول از کشوی صندوقدار خارج می‌شد اما در مغایرتِ صندوق لحاظ نمی‌شد (نمونهٔ اندازه‌گیری‌شده: انتظار ۳٬۳۵۰٬۰۰۰ تومان به‌جای ۵۰۰٬۰۰۰ تومان). اصلاح در `src/core/store.ts`: مرجوعی‌ها تابعِ شیفتِ **فاکتور** شدند و فقط مرجوعی‌های بعد از بسته‌شدن شیفت به دور بعد منتقل می‌شوند — دقیقاً همان رفتاری که قبلاً برای فروش‌ها برقرار بود.
  - `fjcod/tests/refunds.test.ts` (۸ تست) اضافه شد: مبلغ مرجوعی برابرِ «قیمتِ واقعاً پرداختیِ هر واحد» (نه قیمتِ لیست)، بازگشتِ موجودی دقیقاً یک‌بار، ثبتِ یک `stockMove` با `delta` درست، توزیعِ تخفیف روی واحدها، باطل‌شدنِ امتیازِ وفاداری به نسبتِ مبلغِ مرجوعی، کاهشِ نقدِ مورد انتظارِ شیفت، سودِ صفر پس از مرجوعیِ کامل، و ردِ مقدارِ کسری/بیش‌از‌حد/تهی. شمار تست‌ها **۳۳ → ۴۱**.
  - **تأیید مرورگری واقعی:** `CHROMIUM_PATH=/tmp/chromium LD_LIBRARY_PATH=/tmp/al2023/lib E2E_STRICT=1 npm run e2e` → **۱۹/۱۹ مرحله سبز** (ورودِ پنج نقش، صف مشاور، فروش صندوق با بارکد، بستن شیفت، دارک‌مود، viewport موبایل ۳۹۰×۸۴۴، صفر خطای console).
  - **CI:** job جدید `fjcod-e2e` با `npx playwright install --with-deps chromium` و `E2E_STRICT=1` اضافه شد تا نبودِ مرورگر به‌جای skipِ خاموش، خطا بدهد.
  - **محدودیت:** داده همچنان فقط در مرورگر است (بک‌اند/RLS واقعی ندارد)؛ این تست‌ها درستیِ محاسبه را اثبات می‌کنند، نه ماندگاریِ داده روی چند دستگاه را.

## Professional guide
See `PROFESSIONAL_GUIDE.md` in this folder for performance improvements, debugging playbook, and next steps. Update it whenever behavior changes.

- **۲۰۲۶-۱۰-۱۶ (Vercel ignoreCommand)** — `vercel.json` پروژه `ignoreCommand` گرفت: اگر این پوشه از آخرین استقرار موفق تغییر نکرده باشد Vercel ساخت را رد می‌کند (سهمیهٔ ۱۰۰ دیپلوی روزانه دیگر با PRهای پروژه‌های دیگر پر نمی‌شود)؛ اگر commit قبلی در clone کم‌عمق Vercel نباشد یا خالی باشد، exit 1 می‌دهد و ساخت طبق معمول انجام می‌شود (Vercel هر کد جز 0/1 را Failed می‌کند — نسخهٔ اول با exit 128 همین را روی PR #81 نشان داد و اصلاح شد). تأیید: پنج حالت محلی (همان sha → 0، تغییر/ناموجود/خالی → 1). استقرار واقعی Vercel در این محیط بررسی نشد.

- **۲۰۲۶-۱۰-۱۸ (ممیزی کامل + حذف رمزهای متنی)** — دستور کار تازه در `CLAUDE.md`؛ ممیزی در `PROFESSIONAL_GUIDE.md`.
  - **P0 امنیت:** رمزهای اولیهٔ متنی از `src/core/seed.ts` و README حذف شد. حالا هر seed تازه رمز ۸ رقمی تصادفی و یکتا می‌سازد (`src/core/initial-passwords.ts`)، فقط هش و salt تصادفی ذخیره می‌شود و رمزها یک بار روی صفحهٔ ورود نمایش داده می‌شوند.
  - **چرخش خودکار:** `migrate()` حساب‌هایی را که هنوز روی پیش‌فرض‌های افشاشده‌اند با رمز یک‌بارمصرف عوض می‌کند و `auth.rotate-defaults` را در ممیزی ثبت می‌کند. در کد فقط هش است، نه رمز.
  - تست‌ها روی رمزهای ثابت `fx-*` (`tests/setup.ts`) رفتند. یک تست رگرسیون همهٔ متن‌های پوشه را برای رمزهای قدیمی می‌گردد؛ با یک فایل نشت‌دار عمداً امتحان شد و قرمز شد.
  - e2e رمزها را از صفحهٔ ورود می‌خواند.
  - نتیجه: `npm run check` → **۵ فایل، ۴۵ تست سبز** + build (قبل: ۴۱). `E2E_STRICT=1 npm run e2e` → **۱۹/۱۹**، صفر خطای console. تصویر 390×844 صفحهٔ ورود بررسی شد.
  - وضعیت: بازنشسته. Vercel `cham-store-os` از ۲۰۲۶-۱۰-۱۸ از مخزن POINT منتشر می‌شود؛ `vercel.json` این پوشه دیگر به پروژه‌ای وصل نیست.

- **۲۰۲۶-۱۰-۲۰ (بازاجرای کامل گیت‌ها + E2E واقعی در محیط تازه؛ بدون تغییر کد)** — وابستگی‌ها با `npm ci --ignore-scripts --no-audit --no-fund` نصب شدند (بدون اجرای lifecycle script) و هر دو گیت اجرا شد.
  - `npm run check` ✅ typecheck + **۴۵ تست Vitest در ۵ فایل** (`store` ۷، `auth-session` ۶، `initial-passwords` ۴، `core` ۲۰، `refunds` ۸) + build (`dist/assets/index-*.js` ۳۷۶٫۴۱kB / gzip ۱۱۵٫۱۹kB).
  - `E2E_STRICT=1 npm run e2e` ✅ **۱۹/۱۹** با Chromium 153 واقعی (`CHROMIUM_PATH` + `LD_LIBRARY_PATH` از ابزار موقت `/tmp`، نه وابستگی مخزن): ورود/اجبار به تغییر رمز، ۹ ناوبری مالک، صف مشاور → صندوق، فروش با اسکن بارکد و پول خرد، بستن شیفت، dark mode و layout موبایل، **صفر خطای console**؛ پورت preview در پایان آزاد شد.
  - مرورگر از `cdn.playwright.dev` قابل دانلود نبود (خارج از allowlist محیط، `ECONNRESET`)؛ مسیر جایگزین همان درس ثبت‌شده در `docs/directives/00-monorepo.md` بود: بستهٔ npm `@sparticuz/chromium` + `brotliDecompressSync` روی `bin/chromium.br` و `bin/al2023.tar.br`.
