# معماری

## مرزها

سه لایه، با یک قاعدهٔ سخت: **هسته هیچ‌وقت به DOM دست نمی‌زند.**

```text
┌────────────────────────────── لایهٔ نمایش (مرورگر) ──────────────────────────────┐
│ index.html · assets/infinity.css · src/app/{boot,ui,views,state,self}.js            │
└───────────────────────────────────┬──────────────────────────────────────────────┘
                                    │ فقط از طریق APIهای خالص
┌───────────────────────────────────▼──────────────────────────────────────────────┐
│ هستهٔ قابل‌تست (در مرورگر و در Node یکسان)                                        │
│                                                                                  │
│  agent ──► evaluate ──► sandbox(worker|vm)                                       │
│    │          ├── triad (۳ نامزد، ۳ فرضیه، روبریک)                               │
│    │          └── diff (ساخت/اعمال/آمار)                                         │
│    ├── compress + tokens (Token Forge)                                           │
│    ├── reflex (مغزِ بدون کلید)      providers (۴ پروتکل سیم)                     │
│    ├── genome ──► evolution ──► evals (۱۰ تسک + تست پنهان)                       │
│    └── vfs ──► memory ──► zip                                                    │
└──────────────────────────────────────────────────────────────────────────────────┘
```

## مسئولیت ماژول‌ها

| ماژول | مسئولیت | چیزهایی که عمداً انجام نمی‌دهد |
|---|---|---|
| `agent.js` | چرخهٔ اجرا، پیام‌های رویداد، حلقهٔ ابزار | قضاوت دربارهٔ کیفیت کد (کار `evaluate`) |
| `evaluate.js` | آماده‌سازی نامزد، اجرای تست/پروب، امتیازدهی | تولید کد |
| `triad.js` | استراتژی‌ها، فرضیه‌های شکست، روبریک، انتخاب برنده | اجرای کد |
| `sandbox.js` | اجرای ایزوله + مقایسهٔ ساختاری | آگاهی از تسک |
| `diff.js` | LCS، دیف یکپارچه، اعمال سخت‌گیر | ویرایش فایل |
| `vfs.js` | فایل‌ها، نسخه‌ها، عکس فوری، جست‌وجو | ماندگاری (کار `state.js`) |
| `compress.js` | اتمیزه، حذف تکرار، بسته‌بندی زیر بودجه، عصاره | فراخوانی مدل |
| `providers.js` | ساخت درخواست/خواندن پاسخ/SSE برای ۴ پروتکل | ذخیرهٔ کلید |
| `genome.js` | ژن‌ها، جهش، تناسب اندام، انتخاب نسل | سنجش (کار `evolution`) |
| `evolution.js` | اجرای بنچمارک، ارزیابی ژنوم، یک نسل کامل | نمایش |
| `evals.js` | ۱۰ تسک با تست عمومی و پنهان + امتیازدهی | حلِ تسک‌ها |
| `reflex.js` | تشخیص خانواده، سه نسخهٔ مرجع، اسکلتِ صادقانه | ادعای مدل‌بودن |
| `memory.js` | قوانین قفل‌شده، یادداشت، دفتر جریان | ذخیره‌سازی مرورگر |
| `zip.js` | نویسندهٔ ZIP (STORE + CRC32) | فشرده‌سازی DEFLATE |
| `selftest.js` | ۳۰ سنجهٔ مشترک مرورگر/CI | تست UI |

## جریان یک اجرا

```text
goal ──► تشخیص تسک (reflex.taskForPrompt)
      ──► سه نامزد (Reflex یا مدل)
      ──► برای هر نامزد:
             diff vs فایل فعلی
             codebreak → ۳ فرضیه (۲ پروبِ اجرایی + ۱ بررسی ساختاری)
             اجرای تست عمومی + تست پنهان + پروب در سندباکس
             امتیاز ۵ محوره با وزن‌های ژنوم
      ──► selectWinner (امتیاز → فرضیهٔ تأییدشده → اندازهٔ دیف → ترتیب استراتژی)
      ──► snapshot + نوشتن نامزد برنده
      ──► تأیید پس از اعمال (اجرای دوباره روی فایلِ نوشته‌شده)
      ──► reflect: زمان، توکن، فشرده‌سازی، نتیجه → دفتر جریان
```

نکتهٔ مهم: تأییدِ پس از اعمال روی **فایلِ نوشته‌شده** اجرا می‌شود، نه روی متنِ نامزد. اگر نوشتن و نامزد یکی نباشند (باگِ ممکن در لایهٔ ذخیره)، همین مرحله آن را می‌گیرد.

## جریان تکامل

```text
champion (بدون fitness) ──► runSuite: ۱۰ تسک × ۳ نامزد × (عمومی + پنهان + پروب)
champion.fitness = 0.55·benchmark + 0.25·solveRate + 0.10·stability + 0.10·tokenEfficiency
mutate(champion) ──► دقیقاً ۳ جهش با RNG قطعی
هر جهش ──► runSuite ──► fitness
selectGeneration ──► پذیرش اگر (بهترین − قهرمان) > 0.005 و بدون رگرسیون
```

تناسب اندام از شواهد ساخته می‌شود: `suite.mean` از اجرای واقعی می‌آید، `solveRate` نسبت تسک‌های کاملاً حل‌شده است، `stability` واریانس امتیازها را جریمه می‌کند و `tokenEfficiency` هزینهٔ تولید را.

## تصمیم‌های طراحی و دلیلشان

| تصمیم | چرا | هزینه‌ای که پذیرفتیم |
|---|---|---|
| بدون build، بدون فریم‌ورک | استقرار در Netlify Drop و بارگذاری فوری روی موبایل | رندر دستی DOM و نبودِ type-check |
| هستهٔ خالص + UI جدا | یک تست در Node و مرورگر یکسان معنا می‌دهد | کمی boilerplate در `mountX` |
| Reflex به‌عنوان مغزِ پیش‌فرض | اپ باید بدون کلید و بدون شبکه کار کند و همان مسیر را اثبات کند | ۱۰ خانواده، نه کدِ دلخواه |
| سندباکس Worker + `node:vm` | اجرای واقعی بدون به‌خطر انداختن صفحه یا CI | سقف زمانی و نبودِ ماژول‌های ES |
| ZIP با STORE | صفر وابستگی و باز شدن همه‌جا | حجم بیشتر برای فایل‌های بزرگ |
| برآورد توکن heuristic | حجم tiktoken روی موبایل توجیه ندارد | خطای تخمین (محافظه‌کارانه به بالا) |
| سه نامزد به‌جای یکی | تفاوت واقعی در کیفیت و ایمنی؛ و «۳ احتمال» خواستهٔ صریح مالک است | سه برابر تست، اما تست ارزان است |

## نقاط توسعه

- **مغزِ تازه:** یک آداپتر با امضای `complete({messages,system,tools,onDelta,signal})` بساز و در `makeLLM` بگذار. بقیهٔ خطِ لوله تغییر نمی‌کند.
- **تسکِ تازه:** یک شیء در `TASKS` با `files`, `entry`, `cases`, `hidden`؛ اگر خانواده‌اش در Reflex نیست، فقط با مدل حل می‌شود.
- **استراتژی تازه:** در `STRATEGY_META` و `reflex.REFLEX.BUILDERS` اضافه کن؛ `planTriad` و روبریک خودشان می‌فهمند.
- **ژنِ تازه:** در `DEFAULT_GENES` + `LIMITS` + یک اپراتور در `OPERATORS` + ردیف در `GENE_LABELS`.
