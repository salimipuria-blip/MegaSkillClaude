# کنسول آیفون مگااسکیل — دفتر جریان پروژه

> توضیح زندهٔ پروژه؛ هر دور کاری همین‌جا اضافه می‌شود. آخرین به‌روزرسانی: **۲۰۲۶-۱۰-۱۴**.

## ۱) پروژه در یک نگاه
- **پوشه:** `mobile/` · وب‌اپ فارسی PWA برای کدنویسی از آیفون (جست‌وجوی آفلاین مهارت‌ها +
  بازکردن همین مخزن در VS Code آنلاین)
- **منبع داده:** `.claude/skills/mega-skills-router/references/triggers.json` (منبع یکتا) →
  `mobile/skills-index.json` **تولیدی** است؛ دستی ویرایش نشود.

## ۲) دستور دقیق این پروژه
```bash
python3 mobile/build-index.py            # بازسازی ایندکس
python3 mobile/build-index.py --check    # گیت تازگی (در تست‌های ریشه و CI هم اجرا می‌شود)
python3 -m http.server 8000              # از ریشه: http://localhost:8000/mobile/
```

## ۳) وضعیت تأییدشده (۲۰۲۶-۱۰-۱۴)
| بررسی | نتیجه |
|---|---|
| `build-index.py --check` | ✅ «mobile index: OK (**۵٬۷۳۸ مهارت قابل‌مسیریابی**)» |
| هم‌خوانی با مسیریاب | ✅ همان تعداد/محتوا که `triggers.json` می‌دهد (مهارت‌های `incomplete` عمداً حذف می‌شوند) |
| PWA | ✅ `manifest.webmanifest`، `sw.js`، آیکون‌های ۱۹۲/۵۱۲ و apple-touch-icon موجود است |

## ۴) این دور چه دیده شد
- ایندکس تازه است و هیچ drift ندارد؛ تست ریشه (`test_mobile_console.py`) و `--check` هر دو سبز.
- `sw.js` و manifest بررسی شد: مسیرهای نسبی‌اند و در زیرمسیر `/mobile/` هم کار می‌کنند
  (شرط لازم، چون این پوشه درون یک مخزن میزبانی می‌شود، نه در ریشهٔ دامنه).

## ۵) کارهای باز / پیشنهاد بعدی
- [ ] افزودن نسخهٔ ایندکس به `manifest`/`sw.js` (cache-busting) تا بعد از هر
      `build-index.py` کاربر آیفون نسخهٔ کهنه نبیند.
- [ ] آزمون واقعی روی Safari آیفون: «Add to Home Screen» → جست‌وجوی فارسی → «کپی پرامپت آماده».

## ۶) لاگ جریان (فقط اضافه می‌شود)
- **۲۰۲۶-۱۰-۱۴** — `--check` سبز (۵٬۷۳۸ مهارت)؛ بررسی PWA/سرویس‌ورکر؛ ثبت دو بند پیشنهادی.
