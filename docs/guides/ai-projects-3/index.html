۰ چرا این نسخه بازنویسی شد

نسخهٔ اصلی زیبا بود، ولی سه پروژه‌اش «طبق آموزش» بالا نمی‌آمد. چهار ادعا با واقعیت نمی‌خواند:

ادعای نسخهٔ اصلیواقعیت اندازه‌گیری‌شدهاثر
from langchain.chains import RetrievalQA حذف شده روی langchain 1.4.7 → ModuleNotFoundError پروژهٔ ۳ در خط اول می‌شکست
from langchain.memory import ConversationBufferMemory حذف شده کل ماژول langchain.memory نیست همان

«مدل چند ده مگابایت است» ۱٫۱ گیگابایت در حالت پیش‌فرض؛ ۳۱۰ MB با dtype:'q8' کاربر بعد از چند دقیقه تب را می‌بست
«همهٔ ابزارها رایگان و متن‌باز» n8n متن‌باز نیست مجوز Sustainable Use (fair-code) ادعای حقوقی نادرست

این اعداد از فهرست فایل‌های مخزن مدل در هاگینگ‌فیس (encoder_model.onnx = ۵۱۲ MB، decoder_model_merged.onnx = ۶۱۴ MB، نسخه‌های q8 = ۱۵۵ MB) و از اجرای واقعی importها روی نسخه‌های نصب‌شده آمده‌اند.

۱ وب‌سایت هوشمند: خلاصه‌ساز داخل مرورگر

Transformers.js · بدون سرور · بدون API · مدل داخل مرورگر

بارگذاری کتابخانه (پین‌شده)

import { pipeline } from 'https://cdn.jsdelivr.net/npm/@huggingface/transformers@4.3.2/dist/transformers.min.js';

نسخه را پین کن. آخرین نسخه ۴٫۳٫۲ است؛ نسخهٔ ۳٫۵٫۱ آموزش اصلی هنوز روی CDN هست ولی قدیمی است.

مدل، با حجمِ صادقانه

const summarizer = await pipeline(
  'summarization',
  'Xenova/distilbart-cnn-6-6',
  { dtype: 'q8' }        // ← ۳۱۰ MB به‌جای ۱٫۱ GB
);

چهار نکته‌ای که در آموزش‌های معمول نیست

  1. Worker جدا: مدل باید در Web Worker اجرا شود، وگرنه صفحه در حین پردازش فریز می‌شود.
  2. توقف واقعی: فراخوانی ONNX قابل لغو نیست؛ تنها راه، terminate() روی Worker و ساختِ Worker تازه برای اجرای بعدی است.
  3. خواندن خروجی: BART مقدار summary_text می‌دهد، بعضی مدل‌ها generated_text؛ یک تابع readSummary هر دو را می‌پذیرد. علتِ رایجِ چاپ‌شدن undefined همین است.
  4. برش در مرز جمله: قطع‌کردن متن وسط جمله باعث می‌شود مدل ادامه‌بافی کند؛ برش فقط روی . ! ? ؟ … و با حفظ دست‌کم ۶۰٪ بودجه.

«هیچ داده‌ای خارج نمی‌شود» درست است (متن شما جایی نمی‌رود)، ولی «هیچ درخواستی به اینترنت نمی‌رود» درست نیست: خودِ مدل بار اول از CDN هاگینگ‌فیس دانلود می‌شود.

۲ اتوماسیون هوشمند: خبر → خلاصهٔ محلی → تلگرام

n8n + Ollama · یا نسخهٔ بدون وابستگی با Node استاندارد

مسیر گردش‌کار

[Schedule: هر ۶ ساعت] → [RSS Feed Read] → [HTTP Request → Ollama] → [Telegram: Send Message]

همین مسیر در فایل workflow.n8n.json قابل Import است و از نظر ساختار (نودها، اتصال‌ها، نوع نود) اعتبارسنجی می‌شود.

سه دامِ عملی

  • اگر n8n داخل Docker است، localhost یعنی خودِ کانتینر؛ آدرس Ollama باید http://host.docker.internal:11434 باشد.
  • بدون timeout روی نود HTTP، اجرای کند معلق می‌ماند.
  • در parse_mode: HTML هر < در متن خبر، پیام را می‌شکند؛ اول escape کن.

مجوز: n8n تحت Sustainable Use License است و خودش را «fair-code» می‌نامد، نه open source: استفاده برای کارِ خودت رایگان است، فروشِ آن به‌عنوان سرویس به مشتری ثالث نه. اگر این مرز برایت مهم است، نسخهٔ بدون وابستگی همین پروژه (با Node استاندارد) را استفاده کن.

docs = retriever.invoke(question)      # k=4

سه تصمیمی که کیفیت را تعیین می‌کند

  1. امتناع صریح: اگر سندی پیدا نشد، مدل صدا زده نمی‌شود و پاسخ «در اسناد پیدا نکردم» است. ایجنت RAG با زمینهٔ خالی، فقط چت‌بات توهم‌زا با مراحل اضافه است.
  2. ارجاعِ درست: شماره‌گذاری متن و فهرست منابع از یک منبع می‌آیند؛ اگر بخشی به‌خاطر سقف کاراکتر حذف شود، شماره هم حذف می‌شود.
  3. حافظه با فراخواننده: تاریخچه یک لیست پیام است، نه یک Memory حذف‌شده.

برش متن (chunking) در این پروژه ۲۵ خط قطعی و تست‌شده است: پاراگراف → جمله → کاراکتر، با overlap. دلیلش فقط آموزشی نیست؛ کلاس آمادهٔ LangChain به بستهٔ جدا منتقل شده و این پیاده‌سازی بدون هیچ وابستگی تست می‌شود.
