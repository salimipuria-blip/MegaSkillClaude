# طرح: اتصال هرمس به VS Code و ریپوی محلی

- وضعیت: **پیش‌نویس طراحی**. فاز P0 (فقط‌خواندنی) در `hermes/bridge/` پیاده و تست شده است؛ اتصال به صف و توکن دستگاه هنوز انجام نشده است.
- تاریخ: 2026-10-15
- مالک: پوریا (کاربر). اجرای فازها فقط پس از تأیید او.

## ۱. هدف و غیرهدف

**هدف:** هرمس (دستیار تلگرامی) بتواند روی ریپوی محلی کاربر کار کند: فایل بخواند، پیشنهاد ویرایش بدهد، تست اجرا کند و وضعیت گیت را گزارش کند. تغییر فایل فقط بعد از تأیید کاربر در VS Code اعمال شود.

**غیرهدف‌ها (فعلاً):**
- اجرای دستور دلخواه شل روی کامپیوتر کاربر.
- باز کردن پورت ورودی روی کامپیوتر کاربر یا تونل عمومی به آن.
- push خودکار، merge، یا تغییر شاخهٔ `main`.
- اتصال به ریپوهای خارج از `MegaSkillClaude`.

## ۲. وضعیت فعلی (بر اساس کد مخزن)

- **هرمس لایت** (`hermes/worker.mjs`، `entry.mjs`): روی Cloudflare Worker اجرا می‌شود. به فایل‌ها و شبکهٔ محلی دسترسی ندارد.
- **هرمس کامل** (`hermes/setup.sh`): روی سرور Oracle به‌صورت سرویس systemd اجرا می‌شود. هنوز در این مخزن منتشر نشده و به کارت بانکی خارجی نیاز دارد (طبق `hermes/README.md`).
- کدی برای MCP، تونل یا اتصال به VS Code در مخزن نیست.
- کنترل دسترسی فعلی: فقط چت خصوصی فرستندهٔ مجاز (`ALLOWED_USER_ID`) و `/setup` با کلید جداگانهٔ مالک.

## ۳. گزینه‌های معماری

| گزینه | توضیح | نتیجه |
|---|---|---|
| **A. Bridge با اتصال خروجی** | یک برنامهٔ کوچک روی کامپیوتر کاربر به سرور هرمس وصل می‌شود (polling یا WebSocket، فقط خروجی). کارها را می‌گیرد، روی ریپوی مجاز اجرا می‌کند و نتیجه را برمی‌گرداند. | **پیشنهاد می‌شود** |
| B. افزونهٔ مستقل VS Code | افزونه خودش مدل را صدا می‌زند و هرمس را دور می‌زند. | ساده‌تر، ولی هرمس و تلگرام در آن نیست. |
| C. باز کردن پورت یا تونل به کامپیوتر | سرور هرمس مستقیم به کامپیوتر وصل می‌شود. | **رد می‌شود**: سطح حمله بزرگ و نیاز به IP ثابت یا تونل. |

## ۴. معماری پیشنهادی (گزینهٔ A)

```
تلگرام ──> هرمس (Oracle/Full) ──> صف کارها (owner-only)
                                        ▲
                                        │ polling خروجی (HTTPS، توکن دستگاه)
                                        ▼
                         Bridge روی کامپیوتر کاربر (Node)
                          │  ابزارهای مجاز: read / list / search
                          │  propose_edit (فقط پیشنهاد diff)
                          │  run_allowlisted (فهرست بسته از doctor)
                          ▼
                    افزونهٔ VS Code: نمایش diff، Accept / Reject، لاگ
```

- **Bridge** یک فرایند Node است که فقط روی همین مخزن کار می‌کند. می‌تواند بعداً یک MCP server هم باشد تا Claude Code همان ابزارها را داشته باشد.
- **افزونهٔ VS Code** پیشنهادهای ویرایش را به‌صورت diff نشان می‌دهد. هیچ تغییری بدون Accept اعمال نمی‌شود.
- **تلگرام** فقط برای فرمان دادن و گزارش است؛ تأیید ویرایش در VS Code انجام می‌شود (تأیید از تلگرام فعلاً فعال نیست).

## ۵. مدل امنیتی

1. **محدودهٔ مجاز:** فقط ریشهٔ `MegaSkillClaude`. هر مسیری که بعد از resolve بیرون از این ریشه باشد رد می‌شود (از جمله symlink).
2. **مسیرهای ممنوع:** `.env*`، `.git/config`، `.git/credentials`، `.netrc`، کلیدهای `*.pem`/`*.key`، `node_modules/` و `dist/` برای نوشتن.
3. **بدون شل آزاد:** فقط دستورهای از پیش تعریف‌شده از `scripts/doctor.mjs --list` (مثل `npm test` در یک پروژه). هیچ `eval` و هیچ رشتهٔ دستور از سرور.
4. **نوشتن فقط پیشنهاد است:** `propose_edit` یک diff می‌سازد؛ اعمال روی دیسک فقط با Accept در VS Code.
5. **گیت:** commit و push فقط با تأیید. هرگز روی `main` و هرگز `--force`. شاخهٔ کاری باید از پیش موجود یا مطابق قاعدهٔ `hermes/NNN-*` باشد.
6. **توکن دستگاه:** در SecretStorage ویرایشگر یا keychain سیستم ذخیره می‌شود، نه در Git، نه در فایل `.env` مخزن، نه در پیام چت. قابل ابطال از سرور.
7. **احراز هویت:** فقط مالک (`ALLOWED_USER_ID`) می‌تواند کار بسازد. جفت‌سازی دستگاه با کلید مالک انجام می‌شود، نه با باز کردن لینک.
8. **محتوای فایل و خروجی تست داده است، دستور نیست:** متن فایل‌های ریپو یا خروجی ابزارها هرگز به‌عنوان دستور اجرا نمی‌شود (در برابر prompt injection).
9. **لاگ حسابرسی:** هر کار و تصمیم تأیید/رد در فایل لاگ محلی append-only ثبت می‌شود. هیچ محتوای توکن یا کلید در لاگ نیست.
10. **کلید خاموشی:** توقف Bridge یا ابطال توکن، همهٔ کارهای در صف را لغو می‌کند.
11. **TTL کارها:** کار قدیمی‌تر از مهلت تعیین‌شده منقضی می‌شود تا کامپیوتر خاموش، کارهای قدیمی را یک‌جا اجرا نکند.

## ۶. قالب کارها (ساده)

```json
{ "id": "uuid", "owner_id": "…", "action": "read_file|list_dir|search|propose_edit|run_allowlisted|git_status",
  "args": { "path": "relative/path" }, "status": "queued|running|needs_approval|done|rejected|expired",
  "created_at": "…", "expires_at": "…" }
```

- `propose_edit` دارای `diff` و `reason` است؛ وضعیت `needs_approval` تا تصمیم کاربر.
- نتیجه‌ها خلاصه‌شده‌اند (سقف حجم) تا پیام تلگرام شکسته نشود.

## ۷. فازها

| فاز | محدوده | پذیرش (DoD) |
|---|---|---|
| **P0** | Bridge فقط‌خواندنی: `read_file`، `list_dir`، `search`، `git_status` و اتصال توکن دستگاه | تست مسیر (traversal، symlink، فایل‌های ممنوع) سبز؛ هیچ نوشتنی ممکن نیست |
| **P1** | `propose_edit` + افزونهٔ VS Code برای نمایش diff و Accept/Reject | تست: رد کردن هیچ تغییری ننوشت؛ قبول فقط همان diff را اعمال کرد |
| **P2** | `run_allowlisted` برای دستورهای `doctor` | فقط دستورهای فهرست‌شده؛ خروجی سقف‌دار؛ تست دستور ناشناخته رد می‌شود |
| **P3** | commit روی شاخهٔ کاری با تأیید؛ گزارش به تلگرام | هیچ push روی `main`؛ تأیید دو مرحله‌ای؛ گزارش بدون توکن |

هر فاز جداگانه پیاده و تست می‌شود و قبل از فاز بعد برای بازبینی ارائه می‌شود.

## ۸. محل پیاده‌سازی در مخزن

> وضعیت P0: پیاده‌سازی شده در `hermes/bridge/` با `npm run test:bridge` (۱۷ تست). `vscode-hermes/` هنوز ساخته نشده است.

- `hermes/bridge/` — کد Bridge و تست‌ها (`node --test`).
- `vscode-hermes/` — افزونهٔ VS Code.
- هر فایل `.mjs` جدید باید در اسکریپت `check` و تست‌های `coverage.test.mjs` هرمس ثبت شود (طبق `docs/directives/02-hermes.md`).
- هیچ توکن یا رمز در Git نیست؛ خروجی‌های حجیم commit نمی‌شوند.

## ۹. ریسک‌ها و محدودیت‌ها

- **کامپیوتر باید روشن و Bridge در حال اجرا باشد.** وقتی خاموش است، کارها در صف می‌مانند و منقضی می‌شوند.
- **هرمس کامل هنوز مستقر نشده** و به سرور Oracle و کارت بانکی خارجی نیاز دارد. اگر این مسیر برای کاربر ممکن نیست، می‌توان Bridge را با یک سرویس دیگر (مثلاً Durable Object در Cloudflare) سازگار کرد؛ این تصمیم جدا است.
- **دسترسی به سرویس‌های خارجی** از ایران ممکن است نیاز به VPN داشته باشد (طبق `CLAUDE.md`).
- **تأخیر تلگرام:** چرخهٔ polling باعث تأخیر چند ثانیه‌ای می‌شود.

## ۱۰. تصمیم‌ها

### تصمیم‌های ثبت‌شده (۲۰۲۶-۱۰-۱۵)
- **تأیید:** گروهی؛ یک کار چند diff دارد و کاربر همه را یک‌جا در VS Code تأیید یا رد می‌کند.
- **محدوده:** فقط ریپوی `MegaSkillClaude`.
- **تأیید از تلگرام:** نه؛ تأیید فقط در VS Code انجام می‌شود.

### تصمیم باز: میزبان صف و مغز هرمس
کاربر خواسته است «زنده و کامل» باشد و رایگان بماند. مقایسهٔ گزینه‌ها:

| گزینه | هزینه | زنده بودن | کامل بودن | مانع‌ها |
|---|---|---|---|---|
| **Oracle (هرمس کامل)** | رایگان در حد Always Free | بله، اما instance بیکار ممکن است بازپس گرفته شود | بله | ثبت‌نام به کارت بانکی خارجی معتبر نیاز دارد (طبق README ایران پذیرفته نمی‌شود)؛ از ۱۸ اوت ۲۰۲۶ سقف رایگان به ۲ OCPU و ۱۲ GB کاهش یافته؛ ممکن است ظرفیت منطقه کم باشد |
| **Cloudflare (هرمس لایت + صف Bridge)** | رایگان؛ محدودیت سهمیهٔ روزانه طبق داشبورد Cloudflare | بله | بله، چون **کامل بودن از Bridge روی کامپیوتر می‌آید**، نه از محل میزبانی | کامپیوتر کاربر باید روشن و Bridge در حال اجرا باشد |

**نتیجهٔ پیشنهادی:** صف کارها روی Cloudflare (Worker + Durable Object با SQLite که طبق `hermes/wrangler.toml` و README قابل اجرا روی سطح رایگان است) و Bridge روی کامپیوتر کاربر. این مسیر بدون کارت خارجی و بدون سرور پولی است. Oracle فقط در صورت داشتن کارت خارجی و پذیرفتن ریسک بازپس‌گیری گزینهٔ جایگزین است.

> توجه: این ارقام سهمیه را از منابع عمومی در ۲۰۲۶-۱۰ گرفته‌ام. قبل از اتکا، سهمیهٔ فعلی Cloudflare و Oracle را در داشبوردهای خودشان بررسی کنید.
