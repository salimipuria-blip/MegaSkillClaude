# مِتاکد · APEX-01

**مسیر جدید VS Code + Netlify + کتابخانهٔ ۵٬۹۶۴ مهارت:** [راهنمای اجرا](../docs/VSCODE_NETLIFY.md). فایل `MegaSkills.code-workspace` در ریشه را باز و F5 بزنید. `npm run build` خروجی مستقل `dist` را می‌سازد. تنظیمات Netlify اکنون همین خروجی را منتشر می‌کنند. انتشار عمومی Netlify هنوز نیازمند اتصال حساب است.

**ایجنت کدنویسِ خودتکامل — بدون سرور، آمادهٔ Netlify.**

هر تغییری که این ایجنت می‌دهد از سه دروازهٔ سخت می‌گذرد: **سه نامزدِ مستقل**، **سه فرضیهٔ شکستِ اجراشدنی** برای هر نامزد، و **اجرای واقعی تست در سندباکس مرورگر**. بعد از آن هم یک ژنومِ نسخه‌دار روی همان بنچمارک سنجیده می‌شود و فقط اگر بهتر شد، جایگزین می‌شود. هیچ‌جای این پروژه «انجام شد» را بدون خروجیِ دیده‌شده نمی‌گوید.

> نسخهٔ ۳٫۱٫۱ · ۶۰ فایل · ۱۲٬۰۰۰+ خط · **۹۷ تستِ سبز** (۳۰ هسته + ۵ مسیرِ مدل + ۶ سرتاسری + ۵ رابط + ۴ امنیت + ۸ ارائه‌دهنده + ۷ ناوردا + ۴ چرخهٔ عمر + ۸ موتور + ۴ تجربهٔ کاربری + ۳ پروکسی + ۳ استقرار + ۱۰ سخت‌سازی) · **۳۲ سنجهٔ مرورگرِ واقعی** · **صفر درخواستِ بیرونی**

## ۳۰ ثانیه تا انتشار

**نسخهٔ منتشرشده:** <https://apex-metacode-ps88.vercel.app> (production، کامیت `a99d0648`) و <https://apex-metacode-4chhxsyh0-ps88.vercel.app> (آخرین کامیت `8f11964c`) — روی Vercel با ریشهٔ `apex-agent` و بدون build. اگر باز نشد، محافظتِ استقرارِ Vercel روشن است: در داشبورد پروژه، Settings → Deployment Protection → Vercel Authentication را خاموش کن (یا با همان حساب وارد شو).

**راه اول — Netlify Drop:** پوشهٔ همین پروژه (یا فایل زیپِ `release/apex-metacode-netlify.zip`) را در <https://app.netlify.com/drop> رها کن. تمام. `netlify.toml` هدرهای امنیتی، کش و مسیر پروکسی را خودش تنظیم می‌کند.

**راه دوم — CLI:**

```bash
npm i -g netlify-cli
cd apex-agent
netlify deploy --prod --dir=.
```

**لوکال:**

```bash
cd apex-agent
python3 -m http.server 8080      # سپس http://localhost:8080
# یا: npm run serve
```

هیچ build، هیچ `npm install` و هیچ متغیر محیطی برای اجرا لازم نیست. **هیچ درخواست بیرونی هم ندارد:** فونت وزیرمتن (متغیر، ۱۱۲KB، مجوز OFL) داخل `assets/fonts/` است، پس برنامه آفلاین، پشت فایروال و در پیش‌نمایشِ سندباکس هم دقیقاً یک‌شکل دیده می‌شود.

## شش قابلیتِ امضا

### ۱. شورای سه‌گانه (Triad)
برای هر تغییر، سه استراتژی مستقل اجرا می‌شود: **مینیمال** (کوچک‌ترین دیف)، **دفاعی** (اعتبارسنجی و حالت‌های مرزی)، **ساختاری** (تابع‌های کوچک و مستندسازی). هر سه با همان تست‌ها سنجیده می‌شوند.

### ۲. رمزشکن (Codebreak)
هر نامزد سه فرضیهٔ شکستِ **دقیق و اجراشدنی** می‌گیرد:
- `H1` ورودی مرزی (خالی، صفر، نوعِ ساده) باعث خطا می‌شود → پروب واقعی
- `H2` صادراتِ قبلی حذف شده یا بازنویسی کامل رفتار را تغییر می‌دهد → بررسی ساختاری
- `H3` با ورودی بزرگ، زمان یا حافظه می‌ترکد → پروب استرس ۴۰۰ عضوی

پروب‌ها در همان سندباکس اجرا می‌شوند و فرضیهٔ تأییدشده از امتیازِ ایمنی کم می‌کند. یعنی «شک» به تست تبدیل می‌شود، نه به جملهٔ تزئینی.

### ۳. سندباکسِ واقعی
کدِ تولیدشده در یک Blob Worker اجرا می‌شود که در آن `fetch`، `XMLHttpRequest`، `WebSocket`، `importScripts`، `indexedDB` و `caches` **وجود ندارند**. سقف اجرا ۱٫۵ ثانیه است و Workerِ قفل‌شده کشته و جایگزین می‌شود (در CI همان کار با `node:vm` و تایم‌اوتِ هر کیس انجام می‌شود).

### ۴. تکاملِ سنجیده (Genome)
ژنوم شامل ۹ ژن (دما، بودجهٔ کانتکست، عمق پروب، سقف گام، …)، وزن‌های روبریک و قطعه‌های پرامپت است. هر نسل:
1. قهرمان سنجیده می‌شود (۱۰ تسک، تست عمومی + پنهان)
2. سه جهشِ متمایز ساخته می‌شود (RNG قطعی با seed)
3. هر سه سنجیده می‌شوند
4. فقط اگر `improved > ε` و رگرسیون صفر باشد، قهرمان عوض می‌شود — وگرنه همان نسل با دلیل «رد شد» ثبت می‌شود.

«حالت بی‌نهایت» این چرخه را تا سقفِ انتخابی ادامه می‌دهد. بازگشت به قهرمانِ قبلی یک کلیک است.

### ۵. کارگاه توکن (Token Forge)
کانتکست اتمیزه می‌شود (جمله/بلوک کد)، تکرارهای نزدیک با شباهت سه‌گرامی حذف می‌شوند، بر اساس هدف رتبه‌بندی می‌شود و زیر بودجه بسته‌بندی می‌شود. چیزهای محافظت‌شده (قوانین، پیام‌های `protected`، آخرین پیام‌ها) هرگز حذف نمی‌شوند و از حذف‌شده‌ها «عصاره» می‌ماند. نسبت فشرده‌سازی و تعداد واحدها روی صفحه است.

### ۶. فضای کاری و خروجی
فایل‌سیستم مجازی با نسخه‌بندی هر فایل، عکس فوری، دیفِ یکپارچه و بازگردانی. خروجی ZIP استاندارد (STORE، بدون وابستگی) که در Finder/Explorer/`unzip` باز می‌شود.

## اتصال مدل (اختیاری)

بدون کلید، **Reflex** کار می‌کند: خانوادهٔ تسک را از متن تشخیص می‌دهد و برای هر سه استراتژی نسخهٔ واقعی می‌سازد. Reflex یک مدل زبانی نیست و ادعای آن را هم نمی‌کند؛ برای درخواست‌های خارج از ۱۰ خانواده، یک **اسکلتِ صادقانه** می‌سازد و می‌گوید کلید لازم است.

با کلید، همان خطِ لوله با مدل کار می‌کند: مدل در **یک فراخوانی** سه نامزد می‌دهد (JSON)، ارزیابی و انتخاب محلی انجام می‌شود، و اگر تست‌ها قرمز شد، یک دور ترمیمِ سه‌نامزدی دیگر اجرا می‌شود.

| ارائه‌دهنده | رایگان | از مرورگر؟ | یادداشت |
|---|---|---|---|
| OpenRouter | ✅ چند مدل | ✅ | `qwen3-coder` و `deepseek` برای کد |
| Google Gemini | ✅ سطح رایگان | ✅ | برای ساخت کلید از ایران معمولاً VPN لازم است |
| GitHub Models | ✅ | ❌ CORS | توکن GitHub با دسترسی Models |
| Groq / Cerebras | ✅ سقف روزانه | ❌ CORS | سریع؛ از پروکسی استفاده کن |
| Mistral / Together / DeepSeek / OpenAI | 💳 | بیشتر ✅ | کیفیت بالا |
| Anthropic | 💳 | ✅ (هدر رسمی مرورگر) | `anthropic-dangerous-direct-browser-access` |
| Ollama محلی | ✅ | ✅ | `OLLAMA_ORIGINS=http://localhost:8080` |
| پروکسی Netlify | ✅ | ✅ | کلید روی سرور می‌ماند |

**پروکسی (اختیاری، پیش‌فرض خاموش):** در Netlify سه متغیر بگذار: `APEX_PROXY_TOKEN` (رشتهٔ تصادفی بلند)، `APEX_UPSTREAM_KEY` (کلید ارائه‌دهنده) و در اپ «پروکسی Netlify» را انتخاب کن و همان توکن را وارد کن. بدون توکن، تابع `503` می‌دهد؛ هاست‌های مجاز در `netlify/functions/llm.mjs` لیست سفید شده‌اند تا به رلهٔ باز تبدیل نشود.

## معماری

```text
index.html ─ assets/apex.css ─ src/app/{boot,ui,views,state,self}.js
                                      │
              ┌───────────────────────┴────────────────────────┐
              ▼                                                ▼
      src/core/agent.js ────────────► evaluate.js ────────► sandbox.js
        │        │                      │                   (Worker / vm)
        │        │                      ├─ triad.js   (۳ نامزد + ۳ فرضیه + روبریک)
        │        │                      └─ diff.js    (دیف یکپارچه، اعمالِ سخت‌گیر)
        │        ├─ compress.js (Token Forge)   tokens.js
        │        ├─ reflex.js   (مغزِ بدون کلید)
        │        └─ providers.js (۴ پروتکل سیم)
        ├─ genome.js ── evolution.js ── evals.js (۱۰ تسک، تست پنهان)
        └─ vfs.js ── memory.js ── zip.js
```

**قاعده‌های تغییرناپذیر:**
1. `src/core/**` به DOM دست نمی‌زند (تستِ ایستا این را می‌گیرد). همان کد در مرورگر و در Node اجرا می‌شود.
2. هیچ نوشتنی بدون دیف انجام نمی‌شود؛ هیچ اعمالی بدون تأییدِ پس از اعمال.
3. هیچ تستی بدون اجرا سبز اعلام نمی‌شود؛ هیچ جهشی بدون اندازه‌گیری پذیرفته نمی‌شود.
4. کلید فقط در حافظهٔ همین مرورگر؛ در صدور، زیپ و دفتر جریان هرگز نوشته نمی‌شود.

## توسعه و تست

```bash
cd apex-agent
npm run check     # قرارداد ایستا: سلکتورها، آیکون‌ها، ایمپورت‌ها، CSP، بودجهٔ حجم
npm test          # ۹۷ تست: ۳۰ هستهٔ خالص + ۵ مسیرِ مدل (HTTP محلی) + ۳۱ تستِ مرورگر-نما با jsdom
npm run zip       # ساخت release/apex-metacode-netlify.zip + تأیید با python zipfile
npm run serve     # پیش‌نمایش روی 0.0.0.0:8080 با همان CSP و هدرهای vercel.json
npm run render    # ۳۲ سنجه در کرومیومِ واقعی: رندر، فونت، کلیک‌پذیری، سندباکس، موبایل، CSP
npm run render -- --base http://127.0.0.1:8080   # همان ۳۲ سنجه، این بار روی پیش‌نمایشِ در حال اجرا
npm run live      # فراخوانیِ زندهٔ مدلِ واقعی و اجرای همان چرخهٔ Reflex (کلید لازم دارد)
```

`npm run render` تنها ابزاری است که به مرورگر نیاز دارد و اختیاری است: یک‌بار `npm i --no-save puppeteer-core @sparticuz/chromium` و بعد `npm run render`. همان CSP واقعیِ استقرار روی صفحه اعمال می‌شود، صفحه در ۱۳۶۰×۹۰۰ و ۳۹۰×۸۴۴ باز می‌شود، و ۳۲ ادعا سنجیده می‌شود: بوت، فونت وزیرمتن، نبودِ اسکرول افقی، صفر درخواستِ بیرونی، اجرای واقعی Reflex، اجرای ۳۰ سنجهٔ درون‌اپ در مرورگر، اجرای کد در Worker و کشتن حلقهٔ بی‌پایان، و اینکه هر کنترل واقعاً قابلِ کلیک است. اسکرین‌شات‌ها و گزارش در `../docs/screenshots/` می‌نشینند و وارد بستهٔ استقرار نمی‌شوند.

`npm test` برای بخش مرورگر به `jsdom` نیاز دارد؛ اگر نصب نباشد ۳۱ تست (dom، ui، security، lifecycle، ux، hardening) با skip رد می‌شوند و ۶۴ تستِ باقی می‌مانند (`npm i --no-save jsdom`). پنج تستِ مسیرِ مدل به هیچ کلیدی نیاز ندارند: یک سرور HTTP محلی نقشِ ارائه‌دهنده را بازی می‌کند و همان قرارداد را می‌سنجد (هدرِ احراز، نامِ مدل، پرامپتِ سه‌نامزدی، استریم SSE، خطای ۴۰۱، تلاشِ دوبارهٔ ۴۲۹). خودآزماییِ داخل اپ همان ۳۰ سنجه را در مرورگر اجرا می‌کند: **تنظیمات → خودآزمایی**.

## بررسیِ زندهٔ مدل — یک فرمان، دو حالت

هر چیز دیگری در این مخزن عمداً آفلاین است. `tools/live-check.mjs` تنها جایی است که به یک ارائه‌دهندهٔ واقعی وصل می‌شود، چون تنها راهِ صادقانه برای تبدیلِ «اجرا نشد — کلید نبود» به یک نتیجهٔ اندازه‌گیری‌شده همین است.

```bash
export APEX_BASE_URL=https://openrouter.ai/api/v1
export APEX_MODEL=deepseek/deepseek-v3.2
export APEX_KEY=...            # یا: npm run live -- --key-file ~/.apex-key
cd apex-agent && npm run live
```

با این فرمان، همان کدِ محصول (نه یک شبیه‌ساز) اجرا می‌شود: درخواست به مدل، سه نامزدِ برگشتی، اجرای واقعیِ تست‌ها در سندباکس، انتخابِ برنده و تأییدِ پس از اعمال. گزارش در `release/live-report.json` می‌نشیند و کدِ خروج معنادار است: `0` = تأیید شد، `1` = مدل جواب داد ولی تست‌ها سبز نشد، `2` = اجرا نشد (کلید نبود).

```bash
npm run live            # بدون کلید → «NOT RUN» و کدِ خروج ۲ (این هم یک نتیجهٔ واقعی است)
npm run live -- --mock  # بدون شبکه و بدون کلید: اثباتِ خودِ ابزار با یک سرورِ سازگار با OpenAI
```

`--mock` یک سرورِ محلیِ OpenAI (SSE واقعی) بالا می‌آورد و همان مسیرِ HTTP → پارس → سندباکس را می‌سنجد؛ خروجیِ آن `mode: mock` است و هیچ‌وقت به‌جای نتیجهٔ مدل جا زده نمی‌شود. کلیدها هرگز چاپ نمی‌شوند (فقط `abcd…wxyz`) و `.apex-key` در `.gitignore` است.

> محدودیتِ محیطِ ساخت: شبکهٔ سندباکسِ من فقط به `registry.npmjs.org`، `github.com` و `pypi.org` باز است؛ `openrouter.ai` و `api.openai.com` از اینجا `SSL_ERROR_SYSCALL` می‌دهند. پس اجرای زنده باید روی ماشینِ خودت انجام شود — همان فرمان، همان گزارش.

## Apex UI/UX — نقشهٔ انطباق

طراحی از زبانِ بصریِ APEX (سرمه‌ای، فیروزه‌ای، طلایی؛ هستهٔ ذره‌ای در حلقهٔ طلایی) و از قاعده‌های `library/github-skills/ui-ux-pro-max` پیروی می‌کند:

| قاعدهٔ مهارت | پیاده‌سازی |
|---|---|
| کنتراست ≥ ۴٬۵:۱ | متن اصلی `#f0ede8` روی `#050b14`؛ متن‌های کم‌رنگ فقط برای برچسبِ غیرحیاتی |
| هدف لمسی ≥ ۴۴px | همهٔ دکمه‌ها ≥ ۴۰px و در موبایل ≥ ۴۴px؛ نوار پایین ۵۸px — در کرومیوم اندازه‌گیری شده، نه فرض |
| وضعیت فوکوس دیده شود | `:focus-visible` با حلقهٔ فیروزه‌ای ۲px + آفست |
| احترام به reduced-motion | کل انیمیشن‌ها و میدانِ ذره‌ای خاموش می‌شوند |

| z-index مقیاس‌دار | ۳۵ نوار وضعیت، ۴۰ هدر، ۶۰ ناوبری موبایل، ۱۲۰ پالت، ۱۳۰ توست |

| ورودی ≥ ۱۶px در موبایل | بزرگ‌نماییِ خودکار iOS غیرفعال می‌ماند |
| هدف لمسی ۴۴px | در ≤۷۶۰px همهٔ دکمه‌ها، تب‌ها و کارت‌های ارائه‌دهنده حداقل ۴۴px |
| اسکلت/لودینگ | کارت‌های skeleton تا رسیدنِ نامزدها؛ دکمه‌ها در حین اجرا غیرفعال |
| بدون اسکرول افقی در موبایل | سه بریک‌پوینت (۱۲۴۰/۱۰۲۰/۷۶۰) و چیدمان تک‌ستونی |

## نقشهٔ راه

- `P1` اجرای موازیِ سه نامزد (الان ترتیبی است تا نوار پیشرفت خوانا بماند).
- `P1` آداپترِ mehr ارائه‌دهنده با tool-calling استریمیِ کامل.
- `P2` ورودیِ چندفایلی در حالت مدل (الان یک فایلِ هدف در هر چرخه).
- `P2` خدمهٔ آفلاین (Service Worker) برای اجرای بدون شبکه پس از اولین بازدید.
- `P2` صدور زیپِ کل اپ از داخل خودِ اپ (بازخوردِ خودکاوی).
