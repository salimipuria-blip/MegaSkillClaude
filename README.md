# VIKING EXPERIENCE COMMAND

داشبورد فارسی وایکینگ با دو مسیر مستقل:

- `/` — نسخهٔ قدیمی و محلی برای مرور یا استفادهٔ شخصی. دادهٔ آن با تیم همگام نمی‌شود.
- `/team/` — **مرکز فرمان خصوصی تیم اجرایی**: ورود اعضای مجاز، سفرها، وظایف، تجربه‌ها، گزارش‌ها و گالری مشترکِ وابسته به سفر. این مسیر از Supabase Auth، جدول‌های `viking_*` و باکت خصوصی `viking-private` استفاده می‌کند. کد آن در `team/index.html`, `team/app.js`, `team/styles.css` است. برای هر عضو حساب اختصاصی لازم است؛ اشتراک لینک به‌تنهایی مجوز نمی‌دهد.

## وضعیت واقعی

کلاینت تیم برای یک پروژهٔ Supabase پیکربندی شده است، اما وضعیت زندهٔ آن در هر انتشار باید با ورود واقعی بررسی شود. طرح کامل و غیرمخرب پایگاه‌داده، RLS و باکت خصوصی در `sql/viking_supabase_schema.sql` نگهداری می‌شود و محدودیت حداکثر پنج عضو فعال در `sql/viking_limit_five_active_members.sql` است. وجود این فایل‌ها به معنی اعمال‌شدن migration یا آماده‌بودن پنج حساب نیست. مدیر باید ایمیل‌های واقعی را خارج از مخزن دعوت کند و هر عضو ثبت‌نام و ایمیل خود را تأیید کند.

برای رسانهٔ خصوصی: عکس را ابتدا به سفر پیوند بزنید؛ JPG/PNG/WebP/HEIC تا ۸ مگابایت، مشاهده/دانلود/حذف/جایگزینی از فضای مشترک. رمزها، کلید secret و service_role هرگز نباید در کد مرورگر یا GitHub ذخیره شوند. کلید anon/publishable قابل استفاده در مرورگر است؛ حفاظت داده‌ها با RLS انجام می‌شود.

## انتشار و بررسی

این پروژه یک وب‌اپ Static HTML است و برای مسیر `/team/` به npm/build نیاز ندارد. اتصال GitHub به Vercel می‌تواند با هر تغییر در `main` انتشار جدید بسازد. اجرای بررسی‌های استاتیک تیم در `.github/workflows/viking-team-static-check.yml` تعریف شده است. موفقیت Build به معنی موفقیت آزمون ورود واقعی، دسترسی پنج حساب یا آپلود از آیفون نیست؛ این آزمون‌ها باید جداگانه انجام شوند. در محیط فعلی metadata اتصال Vercel و دسترسی شبکه برای مشاهدهٔ deployment موجود نبود، بنابراین نشانی و وضعیت انتشار تأیید نشده است.
