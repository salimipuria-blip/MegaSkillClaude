# Telemetry مسیریابی PSK (اختیاری، پیش‌فرض خاموش)

## خلاصه
- **پیش‌فرض: خاموش.** بدون `PSK_TELEMETRY=1` هیچ خروجی و هیچ ارسال شبکه‌ای وجود ندارد.
- **فقط سمت سرور.** مرورگر چیزی ارسال یا دریافت نمی‌کند.
- **فقط خروجی `console.log` در یک خط JSON** برای هر درخواست مسیریابی (`/api/skills` و `/api/tasks`). هیچ سرویس خارجی، پایگاه داده، فایل، شناسهٔ کاربر، شمارندهٔ سراسری یا کوکی وجود ندارد.
- ماژول: `engine/telemetry.mjs` (بدون وابستگی).

## فعال‌سازی و خاموش‌سازی
- فعال: در Vercel → Settings → Environment Variables، `PSK_TELEMETRY` را برابر `1` (یا `true`) بگذارید، سپس **Redeploy** کنید. تغییر env در Vercel بدون redeploy روی توابع اثر نمی‌گذارد.
- خاموش: متغیر را حذف کنید یا هر مقدار دیگری (مثلاً `0`) بگذارید، سپس Redeploy کنید.

## فیلدهای مجاز (allowlist)
هر خط دقیقاً این کلیدها را دارد (`mode` فقط در `/api/tasks`):

| کلید | معنی | مقادیر |
|---|---|---|
| `evt` | نام رویداد | `psk.request` |
| `v` | نسخهٔ schema | `1` |
| `route` | مسیر | `skills` یا `tasks` (در غیر این صورت `other`) |
| `method` | متد HTTP | `GET`، `POST` یا `other` |
| `status` | کد وضعیت پاسخ | عدد ۱۰۰ تا ۵۹۹، یا `0` اگر نامعتبر |
| `ms` | مدت اجرای handler | عدد صحیح میلی‌ثانیه، سقف ۶۰٬۰۰۰ |
| `results` | تعداد مهارت‌های انتخاب‌شده | عدد صحیح ۰ تا ۲۵ |
| `mode` | حالت درخواست (فقط tasks) | `plan` یا `answer` |

مثال خط خروجی:
`{"evt":"psk.request","v":1,"route":"skills","method":"GET","status":200,"ms":3,"results":15}`

## هرگز ثبت نمی‌شود
متن درخواست یا `q`، `queryTokens`، متن پاسخ مدل، محتوای مهارت‌ها، هدرها (از جمله `Authorization`)، توکن‌ها و کلیدهای API، IP، user-agent، شناسهٔ کاربر، شناسهٔ task، هر hash از متن درخواست، و کل `request`، `response` یا `Error`. ماژول فقط از ورودی‌های اعتبارسنجی‌شدهٔ بالا می‌سازد؛ کلید اضافی ورودی دور ریخته می‌شود.

## رفتار در شکست
- هر خطای ساخت یا نوشتن لاگ بی‌صدا نادیده گرفته می‌شود.
- پاسخ HTTP، بدنه، کد وضعیت و خطای پرت‌شده بدون تغییر می‌مانند (با تست‌ها ثابت شده است).
- خطای handler دوباره پرتاب می‌شود؛ telemetry فقط `status: 500` ثبت می‌کند و متن خطا را ثبت نمی‌کند.

## محدودیت‌های واقعی در Vercel Functions (serverless)
- **نگه‌داری:** خروجی `console.log` به runtime logs همان دیپلوی می‌رود. طبق [مستندات رسمی Vercel](https://vercel.com/docs/logs/runtime)، در پلن **Hobby** این logs فقط **۱ ساعت** نگه داشته می‌شوند. PSK روی Hobby است (بر اساس `docs/QA_REPORT.md`). بنابراین این داده‌ها **ماندگار نیستند** و برای تحلیل روند کافی نیستند؛ برای نگه‌داری بیشتر باید log drain یا Observability Plus را خودتان فعال کنید.
- **تجمیع سراسری وجود ندارد:** هر instance تابع یک فرایند جدا است و شمارنده‌ای بین instanceها مشترک نیست. تعداد درخواست‌ها یا میانگین واقعی از روی این خطوط قابل استخراج نیست مگر با ابزار بیرونی که خارج از این مخزن است.
- **نمونه‌برداری ناقص:** instanceها در cold start ایجاد و ممکن است در هر زمان حذف شوند. هیچ‌گونه ادعای کامل بودن یا شمارش دقیق نمی‌شود.
- **ترتیب سراسری تضمین نمی‌شود:** هر خط یک زمان‌ثبت ندارد؛ برای ترتیب، به زمان ثبت خود Vercel تکیه کنید.
- **بدون ارسال شبکه‌ای از سوی کد:** ماژول `fetch` یا سوکت ندارد؛ تست «پیش‌فرض خاموش» این را بررسی می‌کند.

## تست‌ها
`tests/telemetry.test.mjs` این موارد را پوشش می‌دهد: خاموش‌بودن پیش‌فرض و بدون fetch، فرمت دقیق خط و کلیدهای مجاز، نبودن نشت متن درخواست، توکن، هدر، IP، شناسهٔ task و hash، allowlist و مقادیر clamp‌شده، بی‌اثر بودن خطای sink و خطای `console.log`، حفظ مقدار بازگشتی و خطای handler، و برابری پاسخ API با telemetry روشن و خاموش.

## Rollback
- سریع‌ترین راه: `PSK_TELEMETRY` را از Vercel حذف کنید و redeploy کنید. با این کار کد هیچ خروجی‌ای نمی‌نویسد.
- کامل: revert همین PR. هیچ داده‌ای persist نشده و هیچ migration یا سرویس خارجی وجود ندارد.
